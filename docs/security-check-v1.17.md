### 8. 所見（脆弱性ではありません）

- **所見1（同梱チェッカーの案内先）**：チェッカーの案内は、特定の外部AIサイト（`https://muse.ai/`、Meta のサービス）に利用者を誘導します。チェッカー自身が何かを送るわけではありませんが、一般の方への配布物としては「案内先は特定のサービスである」ことを自覚しておくべき点です。将来、案内先を選べるようにするか、説明文で一言触れるかは、配布側の判断事項です。
- **所見2（テストスクリプトの同梱）**：ZIP には `検査` フォルダーのテストスクリプトが含まれます。このうち `Test-TomoCheck.ps1` は、テストのためにアプリ本体のソースを読み込んで実行する仕組み（`[scriptblock]::Create`、275行目）を含みます。実行対象はパッケージ内の自前ファイルだけで、外部の内容ではありませんし、テストは手動で実行しない限り動きません。ただ「配布物にテスト実行系が入っている」こと自体は、気になる人向けに一言説明できると丁寧です。
- **所見3（トレイ停止時のプロセス特定）**：ウォッチャーを止めるとき、トレイプロセスを「コマンドラインにトレイのスクリプト名を含む powershell」という条件で探して終了します（`TomoWatcher.ps1` の `Get-WatcherTrayProcess`）。自分のプロセスは除外されており、実用上の問題はまずありませんが、同名スクリプトを別途実行している特殊な環境では巻き込む可能性が理論上あります。
- **所見4（診断レポートの中身）**：診断レポートには機器名・ドライブ情報・イベントログ本文などが含まれます。これらは自分のパソコン内にだけ保存され、送信機能はありません。HTML レポートのフッターにも「共有前に個人情報を確認してください」と注意書きがあります。利用者が自分でファイルを誰かに送る場合は、その注意のとおりです。

## v1.17.1 追補（自己点検・2026-11-14）

- 対象：v1.17.1 で新しく増えた面だけ（本体の「その場で更新」適用フロー、ウォッチャーパネルの「最新版を確認」）。v1.17.0 部分の結論は前回点検のまま引き継ぎます。
- 方法：新規コード（`TomoSelfUpdate.ps1` の適用まわり、本体 `Show-SelfUpdateCheck`、パネルの追加行）の静的精読、モックテスト（Test-SelfUpdate 67件・Test-Watcher 75件）、VAIO 実機（PowerShell 5.1）での展開動作の実測。
- **これも開発者本人（七味）による自己点検であり、第三者機関の監査ではありません。**

### 追補1. URL組み立てとタグ検証 ― 問題なし

- ダウンロードURLは、定数ベース `https://github.com/noburin1/tomocheck/releases/download` に、検証済みのタグと、タグから機械的に作る資産名（`TomoCheck_`＋タグの `.` を `_` に置換＋`.zip`）を組み合わせるだけです（`Get-TomoAssetName` / `Get-TomoZipDownloadUrl` / `Get-TomoChecksumDownloadUrl`）。
- タグは `^v\d+\.\d+\.\d+$` への完全一致を通ったものだけを使います（`Test-TomoReleaseTag`、`TomoSelfUpdate.ps1` 41行目）。API応答の `tag_name` がこの形でない場合、状態の Tag は空になり、適用フローには入らず、配布ページを開く案内だけになります。応答内の URL フィールド（`html_url` など）は引き続き一切使いません。
- テストで確認済み：`v1.17`・`v1.17.1-beta`・`v1.17.1/../../etc` などの形はすべて拒否され、ダウンロード試行ゼロで中断します。

### 追補2. チェックサム照合フロー ― 問題なし（世代間ギャップの扱いを所見として記録）

- 適用時は、まず照合用資産（`.zip.sha256`）を取りに行き、ZIP本体より前に照合値を確定します。ZIPの SHA256（`Get-FileHash`）が一致しなければ展開せずに中断し、今のフォルダーには触れません。
- 照合ファイルからは「最初に現れる64文字の16進数」だけを値として読みます。値が読めないファイルは不正として中断します。
- **世代間ギャップの扱い**：v1.17.0 以前には `.sha256` 資産が無いため、対象版に照合資産が無い（404）場合があります。この場合、適用側は**黙って進めず**、「照合用のファイルが無いため完全な照合はできません。中身の形とバージョンだけを確認します」という趣旨を**事前にダイアログで明示し、利用者が了承したときだけ**、構造確認のみで進めます。了承が無ければ、ZIP本体を取得する前で止まります。この経路では完全性が TLS と配布元アカウントの安全性に依存する点は、設計上の許容として **所見（追補）1** に記録します。
- 運用変更：v1.17.1 以降のリリースには `.sha256` 資産を必ず添付します。今回の v1.17.1 リリースで初実施し、匿名（未ログイン）でのダウンロードとハッシュ一致まで確認済みです。
